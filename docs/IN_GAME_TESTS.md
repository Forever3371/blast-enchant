# 游戏内测试清单

装好模组进游戏后照着做一遍，能覆盖到 99% 的坑。**第 0 步和第 2 步最重要**——前者能抓到开发环境测不出的问题，后者是玩家最容易丢东西的地方。

---

## 0. 一键自检（必做，10 秒）

```
/blastenchant selftest
```

需要 OP 或权限等级 ≥ 2（单人游戏开作弊即可）。它会在真实运行环境里检查四件事，结果直接打在聊天栏：

```
===== Blast Enchant 自检 =====
  [通过] 附魔等级上限：组件 + NBT 往返都保持 1000 级
  [通过] 附魔池 Diamond Sword：40 次抽样拿到 9 种可用附魔：[...]
  [通过] 附魔池 Diamond Boots：40 次抽样拿到 7 种可用附魔：[...]
  [通过] 附魔池 Trident：40 次抽样拿到 6 种可用附魔：[...]
  [通过] 附魔池 Bow：40 次抽样拿到 4 种可用附魔：[...]
  [通过] 附魔池 Shears：40 次抽样拿到 3 种可用附魔：[...]
  [通过] 烧炼配方：67 条 blasting 配方已加载，diamond_sword 可查
  [通过] 高炉端到端：钻石剑 -> minecraft:sharpness 1000
结果：8/8  全部通过
```

最后一项目检会**真的临时放一个高炉烧一次**（放在你上方最近的空气位置，跑完自动恢复），所以它是真正的端到端验证，不是纸上谈兵。

任何一条 `[失败]` 都直接说明了问题所在，把这个截图发我即可。

> 关掉这个命令：配置文件里 `enable_selftest_command=false`。

## 1. 手动功能验收

### 1.1 基础流程

```
/give @s minecraft:blast_furnace 2
/give @s minecraft:coal 64
/give @s minecraft:diamond_sword 8
```

放高炉 → 加煤 → 放剑 → 等 5 秒 → 取出。

- [ ] 取出来还是**同一把钻石剑**（不是变成别的物品）
- [ ] 名字变成 `锋利 1000` 之类的附魔名
- [ ] 按住 Shift 悬停能看到附魔行

用命令直接看数据（手里拿着那把剑）：

```
/data get entity @s SelectedItem
```

- [ ] 输出里有 `"minecraft:enchantments": {levels: {"minecraft:xxx": 1000}}`
- [ ] 数字是 **1000**，不是 255

### 1.2 附魔必须"真的能用"

```
/give @s minecraft:diamond_boots 16
/give @s minecraft:trident 4
```

- [ ] 烧靴子只会出 保护 / 摔落保护 / 深海探索者 / 冰霜行者 / 耐久 / 经验修补 这类靴子附魔，**绝不会出锋利**
- [ ] 烧三叉戟只会出 忠诚 / 穿刺 / 激流 / 耐久 这类三叉戟附魔

### 1.3 随机性

- [ ] 连烧 8 把剑，附魔种类不会全都一样
- [ ] 烧出来的附魔等级一律是 1000

### 1.4 不重复加工

- [ ] 把已经烧好的剑**再放回高炉烧一次**，取出来附魔不变（不会每次随机跳变）

### 1.5 其它炉子不受影响

```
/give @s minecraft:furnace minecraft:smoker
```

- [ ] 钻石剑放进普通熔炉 → 烧不动（原版没有这个配方，符合预期）
- [ ] 放进烟熏炉 → 同样烧不动

## 2. 存档与重载（最容易出问题的地方）

- [ ] 把几件烧好的装备放进**箱子**，退出到主菜单，重新进入世界，打开箱子 → 附魔还在、等级还是 1000
- [ ] 把它们放进**潜影盒 / 末影箱**再取出来 → 等级不变
- [ ] 单人游戏里按 `F3+T` 重载资源包 → 手持装备等级不变
- [ ] 服务器上执行 `/reload` → 已烧好的装备不受影响，`/blastenchant selftest` 仍然全部通过
- [ ] 走远一点让区块卸载再回来（或者退到主菜单重进）→ 装备等级不变

> 这一节是重点：原版对附魔等级有 255 的序列化上限，模组是靠三个 Mixin 绕开的。
> 如果哪天别的模组也动了这块代码导致绕过失效，症状就是**装备一存盘就丢附魔或等级变 255**。

## 3. 客户端显示

- [ ] 悬停装备显示 `锋利 1000`，而不是 `enchantment.level.1000` 这种原始翻译键
- [ ] 打开**创造模式物品栏**（上次崩溃就发生在这里）→ 不闪退
- [ ] 打开**铁砧**、把烧好的剑放进去 → 不闪退（等级超出原版上限，铁砧照常能打开）
- [ ] 打开**砂轮**、把烧好的装备放进去 → 能移除附魔
- [ ] 在多人服务器上（客户端 + 服务端都装）→ 别人看你手里的装备、名字显示正常

## 4. 效果真的生效

数据对不代表效果对，这几条确认附魔是"活的"：

- [ ] 烧一把 `锋利 1000` 的剑，去打僵尸 / 骷髅 → 一击秒杀
- [ ] 烧一件 `耐久 1000` 的工具去挖矿 → 耐久几乎不掉
- [ ] 烧一双 `冰霜行者 1000` 的靴子在水上走 → 结冰范围巨大（不会崩）
- [ ] 烧一把 `经验修补 1000` 的工具 → 捡经验时明显回耐久
- [ ] 烧一套 `保护 1000` 的盔甲挨打 → 伤害几乎为 0

## 5. 配置项验证

改完 `config/blast_enchant.properties` 要**重启游戏/服务器**才生效。

| 改什么 | 期望结果 |
|---|---|
| `enchant_level=5000` | 烧出来是 5000 级；`/blastenchant selftest` 的等级断言跟着变成 5000 |
| `enchant_count=3` | 一次烧出 3 个附魔，且互不重复；自检仍通过 |
| `allow_curses=true` | 会抽到 绑定诅咒 / 消失诅咒；自检里"无诅咒"断言自动跳过 |
| `blacklist=minecraft:sharpness` | 剑再也烧不出锋利；自检的附魔池项仍通过（只是种类少一个） |
| `enable_selftest_command=false` | `/blastenchant` 命令消失 |

> 改了 `enchant_level` 之后，客户端 tooltip 想显示得好看，需要在语言文件里补一条
> `enchantment.level.<新等级>`，否则会显示原始翻译键。

## 6. 多模组共存检查（你以后会经常用到）

每加一个新模组，进游戏先跑一次：

```
/blastenchant selftest
```

对照表：

| 自检里哪项挂了 | 说明什么 |
|---|---|
| `附魔等级上限` 失败 | 有别的模组也改了附魔组件 / 等级上限，和本模组冲突（Mixin 被覆盖或顺序问题） |
| `烧炼配方` 失败 | 有别的模组覆盖或清空了 `blast_enchant` 命名空间下的配方 |
| `高炉端到端` 失败但其它都通过 | 有别的模组改了高炉行为 |
| 整个命令不存在 | 模组没加载成功，或被配置关掉了 |

再补充两个通用手段：

1. **看启动日志**（`logs/latest.log`）搜这几个关键词：
   - `InvalidInjectionException` / `Mixin apply failed` → Mixin 注入失败（通常就是命名空间 / refmap 问题）
   - `Critical injection failure` → 两个模组抢同一个注入点
2. **检查 jar 里的 refmap**（`blast-enchant-refmap.json`）：
   每个 Mixin 里用字符串写的方法名，都必须在这里有对应条目；
   缺条目 = 正式环境会崩（开发环境反而正常）。
   这次的崩溃就是这么漏掉的。

---

## 7. 出问题时的自查顺序

1. `/blastenchant selftest` —— 看哪一项红
2. `logs/latest.log` 搜 `Blast Enchant` 和 `blast_enchant`
3. 崩溃报告里搜 `Mixin`，看 `XXX FAILED during APPLY` 那段
4. 解压 jar 看 `blast-enchant-refmap.json` 是否缺条目
5. 用 `tools/production-test/` 在真实服务端复现（见 `docs/REUSABLE_TEST_KIT.md`）
